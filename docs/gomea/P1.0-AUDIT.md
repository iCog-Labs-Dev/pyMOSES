## 3. Optimizer seam: what it receives and returns

* **Receives** an empty `instance_set` (`deme`; `deme.fields()` is the frozen `field_set`),
  an `iscorer` (the `complexity_based_scorer`), `max_evals` (= **the whole remaining global
  budget** when there is one deme, since `local_moses` passes `pa.max_evals - stats.n_evals`),
  and `max_time` (integer seconds).
* **Returns nothing.** It *mutates the deme in place*. Hill climbing appends **every
  evaluated instance** (`deme[i].second = iscorer(deme[i].first)`, `hill_climbing.py`
  "score all new instances"), sets `deme.n_evals = current_number_of_evals`, and sets
  `deme.n_best_evals` (logging only). It also sets `optim_stats` fields on itself
  (`nsteps`, `total_steps`, `total_evals`, `over_budget`) that the "Stats:" log line reads.
* **Budget ownership.** The optimizer self-limits against `max_evals`. `local_moses` counts
  `dex.total_evals()` (the sum of `deme.n_evals`) *after* the call. Nothing interrupts the
  optimizer mid-call, and **HC can overshoot**: it scores a whole batch before checking
  `max_evals <= current_number_of_evals`.
* **What reaches the metapopulation.** `keep_top_unique_candidates` keeps the top
  `min(deme.n_evals, len(deme), max_candidates_per_deme)` instances after `sort_demes`, and
  drops score-tied duplicates whose reduced trees are equal. So the **HC contract is an
  all-evaluated-trials archive**, truncated by the outer merge policy. A GOMEA optimizer that
  appends every evaluated trial reproduces that contract exactly. This is the matched
  archive policy: GOMEA gets neither more nor less than HC.
* **Exemplar exhaustion.** It is handled entirely by `select_exemplar`'s visit counter.
  The optimizer plays no part.

## 4. Representation, fields and sampler

* **Genotype.** `instance` is a `list[int]` of packed 64-bit words
  (`pymoses/moses/representation/instance.py:69`). Fields are described by `field_set`
  (`field_set.py:201`), ordered **contin raw fields, then disc fields (multiplicity > 2),
  then one-bit fields**. Logical discrete values are read and written with
  `get_raw(inst, idx)` / `set_raw(inst, idx, v)`.
* **Domains.** Each disc field `idx` has the admissible values `0 .. multy-1`
  (`disc_and_bit()[idx - begin_disc_raw_idx()].multy`). Bit fields have `{0,1}`. The packed
  width can exceed the domain: a Boolean logical knob has `multy = 3` and is packed into 2
  bits, so **code 3 is representable but illegal**. The adapter must never produce it.
  Boolean problems yield disc fields (logical knobs: absent / present / negated) and no
  contin fields.
* **Default instance.** `instance(fs.packed_width())` (all zeros) is what HC starts from
  (`hill_climbing.__call__`, `init_inst is None`). Value 0 of every knob is the exemplar's
  own setting, so the zero instance decodes to the exemplar (verified by test in P1.1).
* **Contin fields** occupy `depth` raw fields of `{Stop, Left, Right}` each. They are a
  *packed step-instruction* encoding, not categories. **Discrete GOMEA must reject
  representations that contain contin fields** (true for regression problems, never for
  Boolean ones).
* **Decoding safety.** `get_candidate` accepts any in-domain combination and builds an
  independent tree. Reduction changes only the decoded program, never the indexing.
* **Sampler** (`sample_from_neighborhood`, `neighborhood_sampling.py:780`):
  * Each sample starts from `instance(center_inst)`, an independent copy.
  * `lazy_random_selector(dim)` picks `dist` **distinct** logical fields without
    replacement. Bits are flipped. A disc field gets a uniformly chosen *different* legal
    value (`1 + randint_n(multy-1)`; equal to current → 0). So **distance = number of
    distinct logical fields changed**, always legal.
  * Samples are drawn *with replacement* across calls: duplicates are possible, and there is
    no deduplication, no fitness filtering and no evaluation.
  * It draws from the process-wide `randGen()` (MT19937), and requires
    `dist <= fs.dim_size()`.
  * It can be called with `sample_size=1` repeatedly to build `N` independent instances at
    chosen radii. Contin moves can only fire if contin fields exist, which the discrete mode
    forbids.
* **Knob probing** (`build_knobs`, `-B/--reduct-knob-building-effort` and the
  `logical_knob` "disallowed" pruning) runs inside representation construction and is shared
  by every optimizer, because it happens before the optimizer seam. Phase 1 changes nothing
  there, so both arms see an identical schema (contract 6).

## 5. Scoring

* **Direction:** maximise. Boolean `score = -(number of wrong rows)`, so 0 is perfect.
  `penalized_score = score - complexity_penalty - uniformity_penalty`
  (`types.py`, `update_penalized_score`).
* **Comparator:** `composite_score.__lt__` (`types.py:436`) orders by penalized score, then
  **lower complexity wins ties**; NaN is smallest. HC's *local* acceptance uses only
  `penalized_score` (`iscore > best_score`, then `score_improved(best, prev_hi)` with
  `min_score_improv`). GOMEA acceptance uses the full composite comparator: accept the trial
  iff `not (trial < current)`. This is the "non-worse under MOSES's comparator" rule, and
  the outer merge uses the same comparator (`sort_demes`).
* **Invalid programs:** the scorer turns any exception into `worst_composite_score`, so
  there is no separate invalid channel. The oracle counts worst-score returns as invalid.
* **Cache:** `behave_cscore`'s `_cscore_cache` is keyed by the *reduced tree*
  (`_cache_key`, collision-free), which makes it phenotype-keyed and
  representation-independent. That is correct, because the data and scorer are fixed for a
  run. HC and GOMEA share it identically. Any *new* genotype-keyed cache must include the
  schema id (contract 4).
  **Correction:** for the demo problems used in the Phase 1 experiments the cache is
  disabled (size 0) for both arms. Every request is therefore a real evaluation for both HC
  and GOMEA. This was measured: hits = misses = 0 on `-H pa -k 4`.
* **Behavioural scores** are recomputed from the tree at merge time only when diversity,
  boosting, domination or `-t` is enabled (`merging.py:493` docstring). The optimizer only
  deals in `composite_score`.

## 6. Single-deme operation

Without `--enable-fs` (the default), `create_representations` builds exactly one
representation using all inputs, and `optimize_demes` runs one deme with the whole
remaining budget. `n_subsample_demes` defaults to 0 or 1. So the required configuration
(one exemplar → one representation → one deme, all inputs) is **stock behaviour**. It needs
no change and cannot be silently narrowed by feature selection.

## 7. Baseline capability and prerequisite repairs

* Boolean support: demo problems `pa`, `dj`, `maj`, `mux` (`demo_problems.py`) plus table
  problems. `mux -k 2` is the 6-input multiplexer and `-k 3` the 11-input one. Action and
  nominal domains are **out of scope** (the port excludes embodiment/action by design).
* **No correctness repairs are required for Phase 1.** Instance copying, Boolean reduction,
  score accounting and merge are all oracle-tested against classic. Two properties are
  worth recording, and neither changes:
  1. HC can overshoot `max_evals` within its last batch (classic behaviour).
  2. HC's time budget truncates to whole seconds (classic behaviour).

  Because nothing is repaired, **the stock HC is the matched HC**. The comparator is the
  unmodified `-a hc`.
* Phase 2 inventory (not implemented here): contin knobs (`contin_spec` step encoding),
  `contin_bscore`, contin reduction, and `+ - * / sin log exp` in the interpreter are
  ported. There are no per-individual constant pools. Native contin knobs are step-encoded,
  not real coordinates.

Why a port and not a native bridge (the build/integration spike): [C1]'s components take
`std::vector<Node*>` GP trees and armadillo matrices, and its build needs armadillo and
boost. pyMoses has **zero runtime dependencies** and a pure-Python fidelity policy. A bridge
would add a C++ toolchain and armadillo to every user and would still need rewriting around
`Node*`. The statistic, LT and GOM kernels are small (<400 C++ lines), so a narrow port with
golden parity fixtures (a g++-built harness containing verbatim copies of the upstream
functions, §P1.2) is the cheaper and more auditable path.

Upstream facts found, which the port must honour or disclose:

* Entropies use the natural log, and the bias normalizers are computed **once**, on the
  first call (`accu(MI_distribution_adjustments)==0`): diagonal `1/H0(i)`, off-diagonal
  `2/H0(i,j)`. The similarity is then `H(i)/H0(i) + H(j)/H0(j) - 2*H(i,j)/H0(i,j)`, which
  matches Eq. 2 of [P1]. The log base cancels in the ratios.
* In this commit, the ordinary-MI branch is **dead** (`if (false)`). LT-MI is therefore
  reconstructed from that dead branch (`MI = H_i + H_j - H_ij`).
* Upstream divides by `H0 = 0` without a guard (it produces inf/NaN). The port handles it
  explicitly (§P1.2 of the plan) and discloses the difference.
* `NN_chain[0] = (int) randu() * mpm_length` always evaluates to 0, because the cast binds
  before the multiplication. The chain therefore starts at `mpm[0]`, which is itself random
  after the `random_shuffle`. The port reproduces this.
* `DetermineNearestNeighbour` initializes `result` to an index, not a similarity of 0, so
  negative similarities rank correctly. No clamping is needed.
* The linkage-tree root is removed (`FOS.pop_back()`). The random-tree FOS stops merging at
  2 sets, so it never builds a root either.
* GOM: the parent is cloned; FOS order is shuffled per recipient; for each subset one
  **uniformly random donor from the whole population** (a self-donor is possible) is used;
  only changed positions are applied; if no changed position is *active*, evaluation is
  skipped and the change is kept; otherwise the trial is accepted iff non-worse, else
  reverted. There is no FI.

## 9. Risk register and compute envelope

| Risk | Mitigation |
|---|---|
| About 8 ms per evaluation in pure Python, so large populations are costly | profile in the pilot; choose N from {64,128,256} on measured cost; run independent seeds as parallel processes (≤ 20 workers) |
| GOMEA consumes the whole remaining budget in one deme (HC stops itself) | explicit local stopping rules: convergence, stall generations, budget, target. Every reason is logged. The outer allocation is unchanged |
| Donor pool lacks alleles (pure mixing cannot create unseen values) | log per-field coverage and entropy; bounded, sampler-based coverage resampling |
| Constant fields make `H0 = 0` | exclude them from linkage (they stay in the genotype); record them; never divide by zero |
| CLI `--help` fidelity to classic | add GOMEA options without altering classic options; run the full suite |
| Byte-identity of `-a hc` | no HC source edits; a regression test compares `-a hc` output before and after |

Proposed Phase 1 compute envelope: at most 20 concurrent single-threaded processes, at most
6 GiB aggregate RAM, and a wall-time cap of about 6 h for pilot plus confirmation combined.
Results go to `../gomea-results/phase1/` (outside the source tree). Manifests, checksums and
the short report are committed on the branch.
